# LushText

> **Load order:** Agents must always load [SOUL.md](./SOUL.md) first and immediately, before reading the rest of [AGENTS.md](./AGENTS.md), so it can inform how the agent should behave while applying the project guidance below.

A minimalist, fast text editor targeting Libadwaita. Looks similar to GNOME Text Editor but with a left workspace pane, an optional right properties pane, and workspace support.

## Critical: Subagent Approval

Subagents can and MUST ALWAYS be used whenever a skill or command asks for them. Approval to use subagents is already EXPLICITLY GRANTED by default; do not wait for additional per-turn confirmation when a skill or command requires delegation.

## Tech Stack

- **Language:** Rust (MSRV: 1.98.0, pinned toolchain 1.98.0 — the compiler the GNOME 51 SDK's `rust-stable//26.08` ships, Edition 2024)
- **GUI:** GTK4 (0.11) + Libadwaita (0.9) + GtkSourceView 5 (0.11); shipped on the GNOME 51 runtime (GTK 4.24, Libadwaita 1.10, GtkSourceView 5.22), source floor GNOME 50 (GTK 4.22, Libadwaita 1.9, GtkSourceView 5.20; the gtk-rs feature set stays at GNOME 50)
- **Config:** GSettings (`data/dev.cominotti.lushtext.gschema.xml`)
- **Build:** Cargo workspace + Makefile (dev), Meson (Flatpak/installed)
- **App ID:** `dev.cominotti.lushtext`
- **License:** GPL-3.0-or-later

## Architecture

Cargo workspace:

- `crates/lushtext-build-support` — tiny build-script helper crate, including the build-only filesystem boundary used by `build.rs` files that cannot depend on runtime services
- `crates/lushtext-core` — all application logic: data models, services, GTK widgets
- `crates/lushtext` — thin binary entry point plus integration and widget tests
- `crates/gtk-lush/` — GTK Lush family crates (`signals`, `settle`, `tasks`, `viewport`, `widgets` with `ClipBin`, `ViewportSliceBin` and `RenderHoldOverlay`, `proof-harness`, `proof-spine`, `axioms`): stable in-tree platform APIs consumed through workspace path dependencies; governance in `crates/gtk-lush/GOVERNANCE.md`. `axioms` holds the isolated probe and one interactive/`--check` sample per GTK axiom ledger entry
- `crates/gtk-lush-adoption-lab` — second-consumer GTK application for adoption validation; it may depend on several GTK Lush crates but is not a family crate and must stay outside `crates/gtk-lush/`. Its `tests/axiom_probes.rs` (`harness = false`) runs every axiom probe headless; nextest excludes `binary(=axiom_probes)` and `make gtk-lush-adoption-lab` runs `--bins`
- `crates/cargo-gtk-proof` — workspace visual proof tool outside the GTK Lush family: schema validation, corpus replay, PNG/policy proof logic, and the same-session live visual runner
- `workspace-hack` — generated cargo-hakari crate for unified dependency features

### Workflow Role Convention

A workflow is one user-initiated operation with ordered stages (Ctrl+S, workspace search, draft recovery), and each of its modules carries exactly one role:

| Role | File | Owns |
| --- | --- | --- |
| Narrative facade | the workflow's public module surface | ordered stages, intent names, delegation, and each control-flow inversion with its resumption point |
| Seam value objects | with the workflow | identity/freshness/intent bundles that cross two or more boundaries, constructed once at the entry point and validated as a unit |
| Pure policy | `policy.rs` | pure decisions; no `gtk4`, `glib`, `gio`, `libadwaita`, or `sourceview5` imports |
| Coordination | `admission`, `execution`, `retirement`, `watch`, `journal`, optionally prefixed with the stage order served (`index_execution`, `replace_execution`) | timers, budgets, generations, dispatch, durable generation-guarded records; a workflow may own more than one |
| Evidence | `evidence.rs` | one typed surface that is the single source of the workflow's observable state |

Modules that only project the workflow onto widgets are **called presentation
surfaces**, not roles, and are declared in the workflow's matrix row. The
convention is normative in
[`.agents/rules/workflow-convention.md`](./.agents/rules/workflow-convention.md);
per-workflow status lives in `docs/workflow-readability-matrix.md` and the
procedure in the `lushtext-workflow` skill. Amending the convention requires
re-migrating every migrated workflow in the same change.

### Editor and documents

- **Workflow readability**: see "Workflow Role Convention" above and `.agents/rules/workflow-convention.md`, which also holds the **whole-pixel geometry policy** (pure geometry and budget policies take and return whole pixels, `#![forbid(clippy::float_arithmetic, clippy::disallowed_methods)]`, and its table of protected modules).
- **GtkSourceView owns editing**: language detection, syntax highlighting, style schemes, and undo/redo are all delegated to GtkSourceView, not reimplemented.
- **Hidden tabs lay out nothing** (`ui/editor_page/view_attachment.rs`): a background tab's view shows an empty placeholder buffer until its tab is first shown, and again once it is seen laying out while hidden, because a `GtkSourceView` on an `AdwTabView` page validates its whole buffer whether or not it was shown (ledger A81–A83). `LushtextEditorPage::buffer()` is always the **document** buffer; never read the document through `source_view().buffer()`. No view is detached while an assistive technology listens (`ui/at_listeners.rs`) or for a document of more than `VIEW_DETACH_MAX_LINES` (2^18) lines. Paced installs into a background tab queue one priority step below the visible tab's. The full contract is in `ui/editor_page/AGENTS.md`.
- **Editor font and zoom as classes** (`ui/font_zoom.rs`, ledger A86): any reload of a display `GtkCssProvider` revalidates every widget, so font rules load once per base font with one rule set per zoom level, keyed by the class `lushtext-font-<g>-zoom-<z>`, and a zoom step swaps classes and loads nothing. A widget that renders the editor font registers through `font_zoom::follow_editor_font` or `follow_editor_font_monospace` (the only way to add `.monospace`; `make check-font-zoom-registration`). While a swap is pending, `document-settled` is blocked. Rules: `ui.md`, "GSettings Bindings".
- **Buffer-level edit lock** (`ui/editor_page/edit_lock.rs`): a load installation, a whole-buffer replacement and a save keep the document read-only with a counted, move-only `EditLock` whose first-connected `insert-text`, `insert-paintable`, `insert-child-anchor`, `delete-range`, `undo` and `redo` handlers stop the emission unless the edit is the owner's own (`edit_lock::with_own_edit`). Never use `GtkTextView::set_editable` for workflow ownership: the setter invalidates every line. A refused edit changes no text, modified flag, undo history or draft; `accepts_user_edits()` and the accessible read-only state report the lock, and the view's drop targets are off while it is held (`DropTargetHold`).
- **Post-open settle** (`ui/language_catalog.rs`, `ui/editor_page/language_attach.rs`, `ui/editor_page/restyle.rs`): every dispatch from the activation turn until an opened document is settled stays within `B_SETTLE_US`, except recorded toolkit floors. The language list loads in one startup idle; the planning worker guesses the language and resolves EditorConfig; every site that sets a language requests one deferred attach stage, run from a `G_PRIORITY_LOW` idle once input is quiet (the definition parse cannot leave the GTK thread, ledger A67). Syntax is reduced above a per-language size (`SyntaxLanguage::syntax_size_threshold`), and a body above its attach-after-install threshold takes the chunked highlighted install (`model/highlight_chunking.rs`). Dense documents install and replace in paragraph-aligned slices queued below GtkTextView's validation idle (A70), and wrap, zoom, font and tab-width changes reveal outward in `V_SLICE` ranges (A72). Readiness `document-settled` and `tabs[].settle_stage` read the load evidence's settle stage. Rules: `ui.md`, "Dense Documents After Open".
- **Held typing** (`ui/editor_page/held_input.rs`, pure half `model/held_input.rs`): while the edit lock is held, a load is in flight or held text waits, a typed insertion (inside a user action, at the caret, deleting nothing, within `HELD_TEXT_CAP_BYTES`) is held and replayed by one settle dispatch as one user action once the document is whole; every other user edit is refused with a warning. **Held text is never discarded** (a document that cannot take it opens it in a new Untitled tab) and **a close never drops it** (`has_unsaved_changes` = modified or held, in every close collector and the close-safety fingerprint). **A partial buffer is never the user's modification, and never saved**: `is_modified()` stays false while a sliced install or an eviction owns the buffer, no save pre-empts a load in flight (`LoadInProgress`, Save As included), and every save is refused while `buffer_holds_no_whole_document()` holds (`EditorSaveError::DocumentNotInMemory`). The full contract is in `ui/editor_page/AGENTS.md`.
- **Line validation before the paint** (`ui/editor_page/frame_validation.rs`, ledger A37): `GtkTextView` can flush pending line validation inside its snapshot, moving the scroll adjustments after the scrollbars were allocated (`Trying to snapshot GtkGizmo … without a current allocation`). The editor view's allocation is therefore queued on every edit, caret move, tag-table removal and change of a default-style view property, and at `before-paint` after a tag change. **Any new code that invalidates the editor layout inside a frame by other means must queue that allocation too.**
- **Dark mode and transparency**: the GtkSourceView scheme follows `StyleManager::is_dark()` (`rust.md`, "Dark Mode"). `Preferences > Editor > Appearance` has a Background Opacity control that applies to the editor document surface and the Markdown preview background only; the header bar, tab bar, side panels, status/search chrome and minimap stay opaque.
- **Automation spine**: same-user agents and smoke tools discover user operations through the GTK-free `services::action_catalog` contract, mutate state only through normal app/window `org.gtk.Actions`, and observe readiness plus bounded state through the read-only `/dev/cominotti/lushtext/Automation` object implementing `dev.cominotti.lushtext.Automation1`. The reusable client `scripts/lushtext-automation.py` wraps introspection, catalog/snapshot/event reads, readiness waits, catalog-checked action activation, and smoke artifact summaries; keep its commands, statuses, exits, and result fields documented. Use `WaitForReady` with the narrowest named predicate before falling back to broad `WaitForIdle`. Snapshots may expose visible metadata such as paths, titles, counts, and surface state, but never document text, note bodies, draft bodies, local-history contents, complete search result text, or private persistence identifiers. LushText keeps full filesystem permission; portal and sandbox checks remain diagnostics, not a portals-only migration. Any action, D-Bus member, snapshot field, readiness predicate/blocker, automation-client contract, or scenario-helper flag change must update `docs/automation.md` and `docs/automation-reference.md`, then pass `make check-automation-docs` and `make automation-client-self-test`.
- **Document scale policy** (`model/document_scale.rs`, `model/paragraph_boundary.rs`, `model/paragraph_profile_watch.rs`, `ui/editor_page/document_scale.rs`): which features a document can afford is decided from its **paragraph profile**, not its byte size. (1) The decode worker accumulates a `DocumentProfile` (total bytes, longest paragraph, per-threshold counts, and the densest `R_batch` run of paragraphs) inside the existing analysis pass; draft recovery, local-history restore and save-formatting mirror-back profile their bodies on the worker that prepares them. (2) One GTK-matching paragraph-boundary function (`\n`, `\r`, `\r\n` never split, U+2029; not U+2028 or U+0085) backs every install/replacement slicer. (3) `DocumentScale` has **byte tiers** (open 512 MiB, undo and history 64 MiB, save-only history 16 MiB, memory multiplier) that follow the latest loaded or saved bytes, and **presentation features** an editor session holds monotone through `join`: syntax and bracket matching (per-language size gate, or a paragraph above `L_syntax`), minimap, invisibles, automatic search highlighting, `wrap_allowed` (`L_wrap_edit`), and `protected_view` (a paragraph above `L_PROTECT_EDIT`). Saves and installed bodies only join, so **no edit, save, rename, Save As, preference change or search session turns a gated feature back on**; reopening re-profiles. (4) `insert-text` and `delete-range` after-handlers run the pure watch over the buffer's **own lines, which depend on edit history** (ledger A42), read at most `2·R_batch` line lengths, and apply any downgrade **before the emission returns** (A44): the language is cleared, bracket matching, invisibles and search highlighting turn off, and the minimap is retired. They stand down while a load installation or buffer replacement owns the buffer. Edits of a highlighted document are re-analysed in paced steps (`ui/editor_page/reanalysis_pacing.rs`); a session that spends `REANALYSIS_ALLOWANCE_US` without merging removes highlighting (`ReductionReason::EditReanalysis`). (5) Reduced features are reported **outside the text view's allocation path** — one announced status-bar message per session, the document-properties "Editor Features" row, and the editor's accessible description — **never an inline alert**, whose show or hide reallocates the text view. Rules: `ui.md`, "Large-Buffer Preview And Marker Guardrails".
- **Protected View** (`ui/editor_page/protected_view/`, `model/protected_fold.rs`, `ui/protected_fold.rs`): a document whose longest paragraph exceeds `L_PROTECT_EDIT` (50,000 characters) is **view-only, caret-free and folded**: each long paragraph shows a bounded head and its tail is tagged invisible and non-editable. Hidden text never reaches GTK's text APIs — find, copy and save read an immutable `ProtectedTextSource` (Save writes it verbatim), and Print is refused. Reading surfaces are the Line Inspector (`win.inspect-line`, Ctrl+Alt+I), Copy Whole Line (`win.copy-whole-line`), the Protected View menu and the fold gutter; navigation places no caret. Local-history previews and note editors fold at insertion and copy folded selections from their source (`ui/folded_text.rs`). Save As of an unmodified protected document is a byte-exact copy of its file (`editor_io::copy_loaded_file_to_path`). The full contract is in `ui/editor_page/AGENTS.md`.

### Workspace sidebar and file tree

- **Multi-workspace sidebar**: `LushtextSidebar` keeps a fixed top row (a `GtkDropDown` with the aggregate scope `All workspaces` plus one item per workspace, and the new-workspace button) above a scrollable list of `LushtextWorkspaceSection` widgets. `All workspaces` shows every section and is the app-wide aggregate workspace scope; selecting one workspace narrows the shared scope to it and hides the others. Each persisted workspace owns an ordered set of zero or more folders and therefore one section, with one top-level tree per folder in stored order; zero-folder workspaces render as real sections, and no-workspace startup keeps the top row and an empty list. Width presets live in `Preferences > Workspace` (`Small`/`Comfy`/`Large`, 20/30/40 %). Contracts: `ui.md`, "Multi-Workspace Sidebar", and `ui/sidebar/AGENTS.md`.
- **Workspace concept**: a workspace is one named, ordered folder set persisted in `$XDG_DATA_HOME/lushtext/workspaces.json`, plus a shared current workspace scope that targets one workspace or the aggregate `All workspaces` view. Creating a workspace selects it; removing the selected workspace falls back to `All workspaces`. The sidebar owns the `WorkspacesFile`; mutations mark persistence dirty, debounce for 150 ms, and save through `spawn_blocking_then`, serialized so an older snapshot cannot overwrite a newer one.
- **Viewport slice pattern** (`gtk_lush_widgets::ViewportSliceBin`, template child `file_tree_slice`): each section's `GtkListView` is hosted in a bin that advertises the list's full height to the outer scroller, allocates the list only the band the viewport shows, owns its adjustments, and forwards the list's own `scroll_to` and focus scrolling to the outer scroller. `GtkListView` realizes at most about 200 rows for one visible range (`GTK_LIST_VIEW_MAX_LIST_ITEMS`, ledger A1), so **never give a `GtkListView` its entire content as viewport when it can exceed ~200 rows**. Container rules are in `widget-wiring.md`, "Adjustment Ownership Under Custom Containers"; history in `crates/gtk-lush/widgets/CHANGELOG.md`. Tests assert **rendered** rows, not model rows (`crates/lushtext/tests/widget/workspace_tree_virtualization.rs`); a caller waits for a forwarded `scroll_to` on `outer_request_pending()`; and the `workspace-tree-reveal` visual scenario's invariant `workspace-tree-rendered-row-anchors` must be proved by any slice-bin, slice-geometry, scroll-request, section list-host or reveal edit. A "Focus Folder" drill-down focuses the tree on a deep path (other workspaces collapse when `workspace-auto-collapse` is on).
- **Workspace entry visibility**: one GTK-free rule, `model/workspace_visibility.rs::WorkspaceEntryVisibility::admits`: a basename on `workspace-excluded-names` (default `[".git"]`, exact, case-sensitive) is never visible; otherwise a dot-name is visible only while `workspace-show-hidden-files` is on; configured workspace folders are always visible as roots. The sidebar tree, both `(Empty)` probes, the palette file index and content search consume the same value, built by `ui/workspace_visibility.rs` once per refresh pass and passed through the filesystem boundary's `*_with_visibility` traversal. The mode is the stateful `app.show-hidden-files` action (`Ctrl+Shift+H`). `ContentSearchOptions::hidden` is serde-defaulted because it is flattened into persisted history and saved searches.
- **Empty folder detection**: `scan_directory_bounded` peeks one level into subdirectories (up to `lookahead_cap`); a folder confirmed empty shows `(Empty)`, hides its expander, and disables "Focus Folder".
- **Workspace auto-refresh** (`services/workspace_watch.rs`): each section watches only the directories the sidebar has materialized, non-recursively; collapsed or unloaded areas refresh through the `Refresh` button or when expanded. Mailbox, scan-flight and lifecycle-worker contracts are in `ui/sidebar/AGENTS.md`; `workspace-refresh-complete` readiness covers them.
- **Attention-moment workspace refresh** (`ui/window/attention_refresh.rs`, pure half `model/attention_refresh.rs`, cross-cutting): the palette file index and the sidebar are refreshed when the window becomes active and when the palette opens, through their own bounded, debounced paths (`rebuild_file_index()`, `queue_auto_full_refresh()`). The interval is adaptive, from the previous pass's wall time, clamped to 2 s–60 s. A refresh is **refused, never queued**, while any editor is saving, a close transaction is in flight, or a draft autosave is pending. Saving into the workspace indexes the destination directly (`complete_save_as`).
- **File tree uses modern GTK4 model**: `GtkListView` + `GtkTreeListModel` + `GtkTreeExpander` (never the deprecated `GtkTreeView`). File tree labels use the default font and do not follow the editor font or zoom. Never set `autoexpand = true` on a `TreeListModel`.
- **Paced directory collapse** (`ui/sidebar/workspace_section/collapse_execution.rs`, `slice-large-directory-collapse`): every LushText collapse and expansion of a directory row goes through the section's two entry points (`collapse_directory`/`collapse_directories`, `expand_directory`; rule 12 of `make check-workflow-boundaries`). A subtree of at most `DIRECT_COLLAPSE_ROWS` (32) rows collapses directly; a larger one shows its intent in the input dispatch (collapsed arrow through `treeexpander.lushtext-collapsing`, accessible `expanded` false, selection and focus moved to the directory row, subtree scans cancelled) and is then drained: unbound rows (they create no widget, A118) in chunks of `COLLAPSE_UNBOUND_CHUNK_ROWS` from a `G_PRIORITY_DEFAULT_IDLE` source between frames, each turn bounded by `turn_continues`, with O(chunk) path-cache bookkeeping and the removed items handed to the listing retirement; bound rows from a one-shot `G_PRIORITY_HIGH_IDLE` step source between frames (D25: armed by the input, each frame's `after-paint`, the between-frames idle and its own dispatch; the tick callback only requests frames), at most `SIDEBAR_REALIZED_ROWS_PER_FRAME` per frame interval window-wide (GTK replaces every bound row widget a removal touches), or up to `COLLAPSE_DESTROY_ONLY_ROWS` when the removal brings no row into the band; several collapses from one input (the folder header) drain bottom-up; then GTK's direct `set_expanded(false)` over what is left. From intent to any end, every realized row of the subtree is hidden on its row widget (D22, ledger A123): opacity 0, `can-target` false and accessible `hidden`, written again after a row is created or mapped; membership is by tree ancestry against the collapsing rows, never by path, so an overlapping folder's occurrence of the same directory keeps its rows and loads. A `G_PRIORITY_LOW` fallback finishes it while the list is unmapped or its clock starves. Rows carry only what every row shows (D17): the reorder handle and drop surfaces exist on top-level workspace-folder rows (and the shield on every realized row during a reorder drag), the Focus Folder button on focusable directory rows. The arrow (a capture-phase release claim, A119), row activation, the folder header, the reveal, the reorder hover and the expander's class keys reach the entry points; AT-SPI `DoAction`, refresh splices and model resets keep GTK's direct collapse. Readers use `row_shows_expanded`; `refresh_blocks_readiness` and the automation snapshot's `collapse_pending` cover a running collapse.
- **File operations** (per `WorkspaceSection`): the file context menu (New File, New Folder, Rename, Delete), inline rename and the workspace header menu (Add Folder, Rename Workspace, Remove Workspace) follow `ui.md`, "File Context Menu" and "Workspace Header Context Menu". Every filesystem mutation runs on a worker through `spawn_blocking_then` and the boundary's helpers; Delete asks first through an `AdwAlertDialog`; New File/New Folder create a unique temporary entry, add a `FileTreeItem` with `pending_rename = true` that starts inline rename on bind, open created files on confirm, and delete the temporary entry on cancel. Directory renames and deletes update or close tabs by `Path::starts_with` prefix. `workspace_section/scan_execution.rs` deduplicates items already in a store.
- **File peek**: `Space` on a selected sidebar file row opens a read-only `GtkPopover` beside the row (name, path, size, mtime, a bounded text sample or a fallback state) without resizing the layout. It updates with the selection, dismisses on repeated `Space`, `Escape`, click-away, non-file selection, section rebuild or filter hide, and promotes through the sidebar `file_activated` callback so `open_document()` stays the single duplicate-tab and editor-focus authority.
- **Filesystem boundary**: production code uses `services::filesystem` for reads, cheap path status, rich metadata, canonical identity, traversal, mutation, sidecar handling, and durable writes (`rust.md`, "Filesystem Boundary"). Raw backend APIs belong only in the private backend or fixture helpers; content search is the one approved `ignore`-based read-only traversal adapter, while Replace All, undo backup, cleanup and persistence stay on the boundary. Local-history lineage migration falls back to a durable copy **only** when `rename` fails with `EXDEV`; any other failure propagates so a retry resumes. Durable-write crash leftovers are removed only when `filesystem::leftovers::is_sweepable_leftover` holds (exact builder pattern, known tag, foreign pid, regular file, at least 24 h old); startup sweeps the app-data directories once per process, a user workspace is never traversed, and only `filesystem::write::atomic_replace_workspace_file` sweeps the just-written target's own leftovers.

### Window shell and persistence

- **Session persistence**: all open tabs (with cursor position and scroll offset) are saved to one global `$XDG_DATA_HOME/lushtext/session.json`, debounced at 500 ms and saved synchronously on `close_request`; ordered generations keep an older snapshot from overwriting a newer one. Startup loads the draft manifest and session in one background task, reserving the bounded progress-disposal lane first; restore creates at most four pages per GTK turn and admits at most two file-load planning operations at once, and until compact descriptors are available, close merges the persisted descriptors with current pages by stable identity so the unrestored session survives. Contracts: `ui/window/AGENTS.md`.
- **Plain-data disposal ownership**: document-sized worker results reserve bounded transit admission before they cross to GTK, and accepted long-lived state releases its transit slot but keeps a nonblocking handoff to the disposal workers. The lane contract is in `ui/AGENTS.md`.
- **Staged window composition** (`ui/window/composition/`): the window is built whole and revealed in stages, so every dispatch from `open`/`activate` until composition completes fits `B_settle`. `open` and `activate` record one `PendingWindowRequest` and return; stages run from default-idle dispatches; realize and present run in one dispatch, and one dispatch after the first frame reveals the content stack, the sidebar and the properties panel. **The first frame is the first frame painted on the mapped window** everywhere it is reported or gated on. Every object exists from construction, so reads and projections never force a stage; an operation that needs a staged surface visible or focusable calls `ensure_composed(StagedSurface::…)` first (rule 11 of `make check-workflow-boundaries`). Readiness blocker `window-composition`. Rules: `ui.md`, "Staged Window Composition", and `widget-wiring.md`, "Staged Content Reveals".
- **CLI file opening**: `ApplicationImpl::open()` (`app.rs`, `HANDLES_OPEN`) records the files in the pending window request (or presents an already composed window) and returns; the files open through `open_document_from_activation` in bounded activation turns of at most `SESSION_RESTORE_PAGES_PER_TURN` files per idle dispatch once the content stage has run, with the usual duplicate-path, draft-claim and focus rules.
- **Adaptive document-properties shell**: `workspace_split_view` holds the left pane; `properties_layout_view` presents the one `LushtextPropertiesPanel` as the wide `properties_split_view` pane or the compact `properties_bottom_sheet`, never rehosting it. `F9` and the header-bar toggle own document properties. Requested visibility is preserved while compact layouts render one secondary surface. The three breakpoints and the split-view restore are installed before the window is realized (ledger A50). What to write back to the rendered surfaces is the pure, integer-only `plan_shell_reconciliation` in `ui/window/geometry/policy.rs`, the only writer (the properties breakpoint carries no `layout-name` setter, ledger A14/A16); the migration and both restores are the pure `plan_split_view_restore`. Allocation-time sync is runtime-only and writes no settings. Both plans are Kani-proved (`ui/window/geometry/policy/kani_proofs.rs`, `ui/window/geometry/kani_proofs.rs`). Rules: `ui.md`, "Split-View Rules", and `ui/window/AGENTS.md`.
- **Window state persistence**: window size, maximized state, both panes' visibility and width fractions persist in GSettings, written through the coalescing settings writer (`ui/settings_writes.rs`): **no backend write during window construction or before the first presented frame**, one flush per persistence window, a synchronous flush at the last window's confirmed close and at shutdown. The workspace width key stores the preset hint fraction, snapped to the nearest preset on restore; a non-finite stored value resolves to `Comfy`. Visibility keys store requested desktop intent. Rules: `ui.md`, "Window State Persistence" and "GSettings Bindings".
- **Status bar and notifications**: the status bar sits below the `gtk_lush_widgets::ClipBin`-wrapped center shell so it stays visible at tiny heights (`ui.md`, "Status Bar"). Messages live in `services::notifications::NotificationBus` with a 10 s expiry; only a publish or update whose message is the visible status-bar view pulses and announces it, rendering is silent, and the pulse uses `gtk_lush_settle::SupersedingTimer`.
- **Inline alerts**: per-editor `LushtextInfoBar` above the editor for document-state alerts, plus the one window-hosted `preview_document_alert` in preview-only mode; the bus keeps one alert per editor, and renders are silent (announced once, where first perceivable). The preview-only copy forwards clicks through `LushtextInfoBar::activate`, guarded by a `DocumentAlertProjectionTicket`, and releases keyboard focus before it hides (`set_releases_focus_when_hidden`), because GTK otherwise moves focus to a visible ancestor at the next painted frame. The warning-primary action is read, not consumed, on click, so a cancelled dialog leaves the button bound to it. Rules: `ui.md`, "Inline Alerts".
- **Tab duplicate detection**: `LushtextWindow` keeps `open_paths: RefCell<HashSet<PathBuf>>` for O(1) duplicate detection in `open_document()`, updated on open, close, rename and Save As. Detection is **application-wide**: a path another window has open presents that window and selects its tab (`journal_core::draft_open_decision`), because the draft id derives from the path.
- **Load cancellation**: each load gets a fresh `Arc<AtomicBool>` cancel token, checked before and after the boundary read; `cancel_load()` sets it, and the tab-strip detach terminal (`handle_tab_detached`) cancels the closed editor's load.

### Loading, saving and recovery

- **Large file handling**: `load_file_async` checks size through the filesystem metadata boundary and refuses files above 512 MiB (`DocumentScale::for_total_bytes(..).open_allowed`). Every other size- and length-dependent decision comes from the document scale. Files above the undo tier keep `begin_irreversible_action()` permanently open. Protected bodies install in hidden-tail slices that fail closed (`FoldedInstallBroken`) rather than append a head after its tail (`ui.md`, "Large-Buffer Preview And Marker Guardrails"). UTF-8 validation uses `simdutf8`; the decoded-content scans keep a scalar reference as the oracle for property tests and the `editor_bytes` fuzz target, and hand-written SIMD is admitted only under `rust.md`, "Explicit SIMD" (one allowlisted kernel, `services/editor_io/text_scans/health_avx2.rs`). Figures: `docs/benchmarks/transient-file-load.md`.
- **Long-paragraph keystrokes**: GTK lays out the whole edited paragraph once per keystroke, so (1) a paragraph longer than `L_WRAP_EDIT` is shown unwrapped by a no-wrap tag on its **first character** (ledger A53), wrapping again `REWRAP_MARGIN` below it (`model/paragraph_wrap.rs`, `ui/editor_page/paragraph_wrap.rs`, re-checked in the same `insert-text`/`delete-range` emission; writes no preference and no text), and (2) the input method's surrounding-text request is answered with a bounded window of 1,024 characters on each side of the cursor within its paragraph (`ui/editor_page/surrounding_text.rs`, ledger A54); if GTK's handler is not found, GTK's behaviour stays. What remains over `B_interact` is a recorded toolkit-floor exception in `docs/next/long-line-documents.md`.
- **Bounded transient file loads** (`ui/editor_page/load/`): open is a split plan/admit/ingest/install workflow. `services::editor_io::plan_text_file()` keeps only stable file facts and a conservative byte charge; one weak/scalar admission coordinator shared by all windows admits ordinary loads within a 256 MiB process budget and runs a supported overweight load exclusively; a `TransientLoadPermit` survives through GTK installation. Ingestion streams through the boundary with identity revalidation. Small text installs directly; everything else clears and inserts in bounded, paragraph-aligned turns while document projections stay suspended. **Only exact finalization publishes `Loaded`**, and cancellation or replacement releases admission exactly once.
- **Bounded transient saves and async save** (`ui/editor_page/save/`): a weak/scalar queue, then byte-weighted admission sharing the 256 MiB transient budget with loads, snapshot (large buffers in independent UTF-8 chunks, no whole-body string returning to GTK), transformation, encoding and the durable write, all under one typed permit released exactly once. Every request revalidates editor lifetime, save generation, destination and close-session identity. The document is held read-only by the edit lock for the whole save; duplicate requests return `SaveInProgress`, and close flows are blocked while any editor is saving. **The modified dot is cleared only after the durable write succeeds**; a failure before the rename keeps the previous bytes and the document modified (`EditorSaveError::WriteTemp`), and a failed directory sync after it is a distinct `EditorSaveError::DurabilityUnconfirmed` warning that also keeps the document modified. The write protocol is the I/O-free, Kani-checked `services/filesystem/write_protocol.rs` core, executed one backend call per action by `services/durable_write.rs`. Close-triggered multi-tab saves have the highest priority and run one editor at a time (`ui/editor_page/AGENTS.md`).
- **Live editor memory budget** (`model/editor_memory.rs`, `ui/window/editor_memory_eviction/`): each editor contributes an O(1) estimate from `GtkTextBuffer::char_count()` (four bytes per character, the on-disk size as a floor), and accounting never copies buffer text. The pure policy applies a 256 MiB budget with 90 % low-water hysteresis and least-recent-use selection (Kani-proved). The window applies at most one candidate per idle dispatch and revalidates it immediately before eviction; active, modified, untitled, saving, loading, failed-load and otherwise non-recoverable pages are never evicted, which makes the budget soft rather than risking user work.
- **File monitoring**: each file-backed `EditorPage` has a `gio::FileMonitor` (started in `open_document`, cancelled on close and dispose), debounced 500 ms; the "File Has Changed on Disk" bar shows only when the mtime differs from `last_known_mtime`, which load and save success update so the app's own writes never trigger it.
- **Draft persistence** (`services/draft_service/`, `ui/window/drafts/`): unsaved buffers are written to `$XDG_DATA_HOME/lushtext/drafts/` with a `manifest.json`. Path-backed ids are the stable path hash shared with sidecar identities; new untitled tabs use collision-resistant `untitled-…` ids. Autosave snapshots, writes and releases one body at a time, then commits the manifest once.
  - **Write-ahead registration**: every file-backed candidate id the persisted manifest lacks is registered before any body is written, and a body write takes the `RegisteredDraft` token only registration mints, so a body without a manifest entry is unrepresentable. An unregistered body found at startup is attributed to its session tab (with `UNPROVEN_BACKING_MTIME_SECS`, so it is never applied over the file) or moved, never deleted, into `drafts/set-aside/`.
  - **Stale drafts are never applied over the file and are always preserved**: a draft whose recorded mtime differs from the file is preserved as a local-history snapshot when policy accepts it and in every case copied byte-identically into `drafts/set-aside/` before it is retired; if preservation fails, nothing is retired or restored. A restore the user pre-empted by editing is preserved the same way, and autosave never writes a body for an id whose restore is pending.
  - Autosave, close-time capture and periodic local-history capture never snapshot a buffer a load installation or whole-buffer replacement owns (`LushtextEditorPage::draft_capture_blocked`).
  - `draft_dirty` clears only after same-id, same-generation body plus manifest acceptance; every failure stays retryable. Deletion removes the body before retiring its manifest entry, with an in-memory tombstone until both stages finish.
  - One draft-owed operation, `LushtextWindow::note_draft_owed` (`drafts/autosave_execution.rs`), marks a tab draft-dirty (advancing its generation, so an older pass cannot clear it) and schedules the first-dirty autosave. The buffer handlers call it for edits; a whole-buffer replacement suspends them, so every replacement terminal that installs text the draft does not hold (local-history Restore and Undo Restore, a set-aside draft opened) calls it too, plus `reproject_modified_indicator` for the "•" title. Startup draft recovery re-projects the title only: its draft already holds the body (`restore-main-ci`).
  - Bounds: 64 MiB per draft; 64 MiB of eager bodies at startup (the rest stay lazy); manifest repair pages 256 entries and may replace the manifest only after a complete, unambiguous inventory within the 2,048-entry and 512 KiB caps — a partial repair stays untrusted and never authorizes cleanup. Orphan cleanup is a deferred two-phase workflow under the same stable target guard as body writes, and it re-validates the inspected inode before removal.
  - Every journal decision comes from the GTK-free, Kani-checked `services/draft_service/journal_core.rs`. **The journal is one per application, not per window** (`ui/window/AGENTS.md`).
  - **Set-aside retention: surface, never auto-delete.** `Preferences > Data` (`ui/preferences/preserved_drafts.rs`) lists the newest 256 preserved bodies within a `MAX_SET_ASIDE_SCAN_ENTRIES` (16 Ki) scan, with Open, confirmed Delete, and a confirmed Delete All that re-fingerprints each listed body before removal. A set-aside name counts as kept only when it holds a byte-identical copy. A soft bound (`set_aside_retention.rs`: 128 bodies or 256 MiB) produces one rate-limited status warning pointing to `app.review-preserved-drafts` (`ui/window/set_aside_review.rs`); no bound, startup, notice or review path deletes a body.
- **Save-changes dialog**: an `AdwAlertDialog` (Save Changes?, Cancel / Discard / Save) on tab close and window close; with several unsaved files, one row with a check button per file. Unchecked files lose their drafts as on Discard; checked files go through the sequential close-save admission one editor at a time, and any failure keeps the remaining tabs and drafts recoverable. A confirmed window close disables input across its asynchronous yields, fingerprints every editor's identity, content generation, modified state and path, and revalidates that fingerprint plus active saves before destruction; a freshness or session-save failure restores sensitivity and retryable drafts instead of closing. Tab close uses `close_page_finish(confirmed)`; the `close-tab` action only calls `tab_view.close_page()`, and teardown happens once, in the detach terminal.
- **Local history** (`services/local_history_service.rs`, `ui/window/local_history/`): saved files keep a lineage under `$XDG_DATA_HOME/lushtext/local-history/` keyed by the canonical-path identity, captured on background threads: the pre-edit baseline, periodic snapshots every five minutes while modified, and each save. Above 16 MiB capture is save-only and above 64 MiB local history is off. A restored file-backed draft is continuity of unsaved work and mints no fresh baseline. Save As starts a new lineage; sidebar renames migrate it. Restore and Undo Restore reserve current-buffer ownership before capture, persist the safety snapshot before mutating, and keep the prior body in its disposal guard (`ui/editor_page/AGENTS.md`). The browser opens from the main menu, the palette, `Ctrl+Alt+L`, the sidebar and editor context menus.
- **EditorConfig support** (`services/editorconfig.rs`, `editorconfig-parser`): overrides are resolved on a worker by walking up from the file's directory, stored per editor, and win over the GSettings fallback when `Some` (`apply_formatting_settings()`), gated by `use-editorconfig`. Supported: `indent_style`, `tab_width`, `indent_size`; the status bar shows an `EditorConfig` badge while overrides apply. Deferred properties: `docs/next/editorconfig-future.md`.
- **Save As** (`window/dialogs.rs`, `FileDialog::save()`): `set_file_path()` updates the path and requests the language attach again under the document scale, which keeps a gated feature off.

### Search, palette, notes and preview

- **Lists are bounded by retained bytes, not counts** (`model/list_budget.rs`; pattern in `widget-wiring.md`, "Large Lists"): workspace search results, sidebar directories, palette categories and the notes browser charge each row against a retained-byte budget, apply rows in time-sliced batches (one splice per touched store per turn), and state any cut as "Showing X of Y …", announced once and reported in the automation snapshot.
- **Directory budget** (`services::file_tree::scan_sidebar_directory`, `ui/sidebar/`): a sidebar directory has no entry-count cap; its scan charges each row against `SIDEBAR_DIRECTORY_RETAINED_BYTES` (512 MiB), is one pass when the directory fits, and ends a cut listing with a "Showing X of Y entries" row (`DirectoryPlaceholder::Budget`). Rows are spliced in 256-row batches; a multi-turn load shows a "Loading entries… X of Y" row and keeps `workspace-refresh-complete` pending. The path caches are spliced per applied batch for the directory's live owning store only (`splice_child_cache`). A collapse is paced (see "Paced directory collapse") and retires the listing afterwards, in 4,096-row slices at `G_PRIORITY_LOW`.
- **File index arena, cap and incremental mutation** (`services/palette/index/`, `scale-file-index`): the index is an interned arena, not one owned row per file. `arena.rs` holds 12-byte file records (directory id, name span in one `names: String`, flags) and 32-byte directory records (parent, name, display root, canonical root, folder); `paths.rs` rebuilds a file's display and canonical paths from its directory chain, so `IndexedFile<'a>` is a view and `SearchResultItem::File` carries a `FileOrdinal(u32)` (16 bytes, pinned). Identity is **derived**: `realpath` runs once per workspace folder and once per symlink entry (`FileIndexBuildMetrics::canonical_resolutions`), and every other file's canonical path is its directory's plus its name; a symlinked file keeps an explicit identity in a sorted `file_extras` table, and a non-UTF-8 name keeps its exact bytes there. Two sorted `u64` key tables (path hash top bits plus ordinal; canonical keys for every file with a canonical, display keys only for files without a derived one) answer duplicate, removal and open-tab lookups in O(log n), each hit confirmed by an exact path comparison (a test-only hasher forces collisions). `FileIndex::rebuild` (`traversal.rs`) skips `IGNORED_INDEX_DIRS` (palette index only) and truncates at 1,048,576 files (`MAX_INDEXED_FILES`, the query-latency bound), 1,048,576 distinct canonical directories, 128 MiB of construction ownership or 64 MiB installed (the memory bounds), with a typed reason and a usable partial index; every arena growth and scratch is charged before it happens, including each file's keys and the per-directory hashers the finish builds the key tables with, so a byte-truncated build always publishes its prefix. Mutations (`mutation.rs`) run in a batch that ends with `finish_mutation_batch`: removals mark records dead, adds and renames grow vectors by `capacity / INDEX_INCREMENTAL_GROWTH_DIVISOR` (never doubling a shrunk vector), dead name bytes are compacted when they pass a quarter of the weight (or mid-batch when an add would otherwise be refused), and a directory rename rewrites one record, not its descendants. Create/delete/rename batches mutate an `Arc<FileIndex>` snapshot on one serialized worker; a full replacement advances the index generation, and stale-worker mutations replay against it before newer ones. The empty query's open-tab count comes from the key table (`OpenTabExclusion`, `RestCount::Known`), not a walk. The retained per-file index lives on as `index/reference.rs` (`test-utils`), the oracle of the `index_parity` property tests. The category view lists at most `MAX_CATEGORY_VIEW_ROWS` (131,072) rows, because a far select-and-scroll grows with a list's rows (A95).
- **Search debounce and ownership**: the palette debounces queries 150 ms (`gtk_lush_settle::Debounce`; empty queries submit at once) and the index rebuild 300 ms. Direct and debounced entry points share one GTK-free one-active/one-latest coordinator, and only a current open-palette generation may splice rows or own readiness. Note-body matching is streaming and cancellable, with nucleo scoring limited to 4 KiB per field; any pruning must stay equivalent to the unpruned reference.
- **Bounded deterministic palette ranking**: palette and Recent Open share `services::fuzzy::FuzzyQuery` (`nucleo-matcher`, one `Matcher` and buffer per query). Source scoring keeps the requested top-N in a worst-first heap and final-sorts by score descending, then source ordinal ascending; empty queries take source order without scoring. Candidate loops check generation cancellation at a bounded interval.
- **Palette "More" rows and category views** (`ui/command_palette/category_model.rs`): a group cut by the 64-row cap ends with one `PaletteSearchRow::More` row stating the exact hidden count. Activating it (or `win.set-command-palette-category`) shows the whole category over a lazy `PaletteCategoryModel` ranked on the worker as `u32` source ordinals, bounded by `PALETTE_CATEGORY_RETAINED_BYTES` (8 MiB); its first 64 rows equal the grouped rows. One query flight serves both views, publishing only for the current generation and category. Escape leaves one level (`PaletteEscape::LeftCategory`; the dismissal ladder's `CommandPaletteCategory` rung); Backspace leaves only after a key release on the empty query (ledger A97).
- **Notes browser and palette rows** (`lighten-notes-browser-rows`; rules in `ui.md`, "Realized List Rows"): their text is `LushtextRowText` (`ui/row_text/`), never `GtkLabel` or `GtkInscription` (ledger A108, A109): a covered text's height comes from its font's cached line metrics, a text needing a fallback font is measured exactly, and the palette's name and subtitle report their shaped width. A first publish into an empty lazy list is staged (`list_budget::staged_first_rows` 32 rows, then `LIST_GROWTH_STEP_ROWS` a frame, `ui/list_growth.rs`); keys and far selections finish it, and the evidence reports the final length. Realized rows are retired in slices after the list is unmapped (`ui/list_retirement.rs`, A110), never inside the close or Escape dispatch; re-entering a category cancels the retirement and publishes over the rows left, and until that publish the view lists no rows of its own (`category_rows_current`).
- **Bounded Recent Open ingestion**: `recent-documents.json` is read through `filesystem::read::bounded_bytes(MAX_RECENT_DOCUMENTS_BYTES)`; cap-plus-one or after-metadata growth never parses the enlarged body and takes the bounded reset/prune path, leaving the Open popover search and file chooser usable.
- **Bookmarks and rich notes**: notes exist only for saved files or explicit workspace folders, as sidecar JSON keyed by `DocumentSidecarIdentity` (a hash of the canonical path), so Save As starts a new identity and in-app renames migrate sidecars; folder notes use a canonical-folder identity, so re-adding a folder restores its note. Open editors project bookmarks as `GtkSourceMark` gutter icons. `Browse Notes` and `Browse Bookmarks` are modes of one live dialog and bounded source/query owner, mode participating in every generation; the browser lists every admitted row in a virtualized `GtkListView` over `ui/window/notes/row_model.rs` with no row or sidecar count (byte ceilings stay; a refused row is skipped and counted), and publishes a projection as a removal then an addition (ledger A93). No unrestricted aggregate bookmark collector exists in production. Untitled tabs surface explicit feedback instead of creating note state. Contracts: `ui/window/AGENTS.md`.
- **Content search panel** (`ui/search_panel/`, `services/content_search/`): Ctrl+Shift+F toggles a workspace-wide grep panel below the content stack (`GtkRevealer`, slide-up 250 ms) over the shared current workspace scope. It is compact when empty (`results_scroll` hidden until the first match). Ctrl+F and Ctrl+H close it first, then open the in-editor bar. The service uses `ignore::WalkParallel` with `grep-searcher`/`grep-regex`; one immutable plan canonicalizes and de-duplicates roots, keeping first-folder precedence. Results stream through a bounded `crossbeam_channel` (1,024) polled every 50 ms into a two-level `GtkTreeListModel`, charged against `SEARCH_RESULTS_RETAINED_BYTES` (256 MiB) with no match-count cap; past the budget the walk keeps counting, the panel states the cut and does not save the search to history. Displayed line content is cut at 500 bytes on a character boundary. Panel GSettings keys: `search-panel-visible`, `search-case-sensitive`, `search-regex`, `search-whole-word`, `search-panel-options-expanded`, `search-gitignore`. Single-flight, retirement and journal contracts: `ui/search_panel/AGENTS.md`.
- **Match navigation**: F4 / Shift+F4 (`win.search-next-match` / `win.search-prev-match`) walk a flat `match_positions` index in arrival order, open the file at the line through `open_file_at_line`, and select the row; the actions are disabled with no tab, a hidden panel or no results (`update_search_navigation_actions()`), and a new search resets the index.
- **Search progress, history and saved searches**: the service emits `SearchEvent::Progress` every 100 files (best-effort `try_send`); the GTK receiver charges every event to one 256-event per-turn budget; the status bar shows "Searching X files…" after 500 ms with a 1 s heartbeat. Recent searches (at most 32, `services/search_history.rs`) are saved on `Done` only when there were matches, de-duplicated to the top. Named saved searches (`services/saved_searches.rs`, a separate file) have no cap and no de-duplication. Restoring either sets every toggle and searches once, behind the `restoring_history` guard.
- **Multi-file Replace All** (two-phase, streamed; `services/content_search/replace/`): "Replace All" generates a preview (`generate_replacement_preview()` in `model/content_search.rs`) with one check button per match; "Confirm Replace" applies only checked rows of the current preview generation, skipping modified open tabs. Apply and undo share one transaction gate that reserves the journal generation before the worker starts, and the journal is one per application. Each file is **streamed** (`replace/stream.rs`, `REPLACE_STREAM_CHUNK_BYTES` per read, never the whole file in memory) in two passes under the editor save's stable target guard: pass A writes the original bytes as a raw undo body (`replace-backup-journal/bodies/<hash>.body`) and computes both digests, the file's descriptor entry is durably journalled, and only then does pass B stream the replaced bytes through `atomic_replace_workspace_file_stream`. The per-file order is the I/O-free `replace/protocol.rs` machine (P0–P6, undo U0–U3; entry removed before its body), Kani-checked in shard `core-replace-protocol`; the stream's UTF-8 seams are proved in `core-replace-stream` and its line logic is checked exhaustively over a bounded domain by a unit test. Files up to the open tier (`MAX_REPLACE_FILE_BYTES` = `REFUSE_TO_OPEN`, 512 MiB) are rewritten; admission replays `main`'s per-file and aggregate limits (`replace/admission.rs`, `MainAdmissionLedger`) so no file `main` replaced is displaced, and admits more only while `REPLACE_DISK_RESERVE_BYTES` (1 GiB) stays free. Every skipped or partly replaced file is reported by reason (`ReplaceSkipReport`, bounded by `MAX_REPLACE_SKIP_LIST_BYTES`) behind **Show Skipped Files** (`ui/search_panel/skipped_files.rs`, a lazy list), whose rows are **Open and Replace in Editor** (`win.replace-in-editor`: the file opens at its first skipped line with the in-tab bar prefilled from the run's request, a regex template translated by `rust_replacement_to_gtksourceview`, ledger A127; nothing is written); a run in one window refuses an apply or Undo in another and retires every window's Undo (`ui/search_panel/journal.rs`); a run reports progress after the search-progress delay and can be cancelled (`win.cancel-search-panel-replacements`), which rolls back every file it rewrote. Undo streams each body back after checking the file still holds the replaced digest. The journal survives panel hide, Escape, ordinary close and new searches; after a crash a valid active journal is offered as Undo, and a legacy inline journal from an older build still loads and undoes. Open unmodified tabs reload afterwards with `last_known_mtime` updated. Replace Preview and skip diagnostics are content-free: logs, status summaries, automation snapshots and debug output carry only bounded typed reason counts and paths, never source substrings or replacement expansions. Contracts: `ui/search_panel/AGENTS.md`.
- **Minimap marker binning** (`ui/editor_page/minimap/`): the marker strip decides per **pixel row**, asking each kind's index at most once per row group, so **no kind has a count cap**. The search context is asked only on a completed scan (`occurrences-count >= 0`, ledger A100), with a bounded private copy of the band's text for interim marks. Modified-since-save lines are one property-less `GtkTextTag` per generation; a clean transition swaps in a fresh tag and retires the old one in low-priority slices. The `minimap-refresh` readiness blocker covers a scan wait and a retiring tag.
- **Minimap availability**: availability comes from the document scale alone (`DocumentScale::minimap_allowed`), decided before any `GtkSourceMap` is attached (`MinimapAvailability::Reduced`; automation reports `minimap-too-large`). Wrapped-layout analysis feeds markers only and is admitted from the O(1) `estimated_live_buffer_bytes()`. **Never clear a live map's `view`** (ledger A32): retire it (`retire_native_source_map`) and attach a fresh one later (`attach_native_source_map`); a retired map must be finalized (`retired_maps_alive` evidence expects 0, ledger A52). The fit functions are Kani-proved (`ui/editor_page/minimap/policy/kani_proofs.rs`).
- **Markdown preview** (`ui/markdown_preview/`, `window/preview.rs`): `pulldown-cmark` events render as `GtkTextTag`s on a read-only `GtkTextView`, with anchored widgets for tables, local images and GtkSourceView code blocks. Planning runs off GTK into bounded projection batches (one-active-plus-latest; source, event, structural, embed and retained-byte budgets); GTK applies at most 256 events and 256 KiB per turn, and limit hits produce accessible limited, fallback or `Simplified` terminals. Three window-level states — editor-only, side-by-side (`toggle-preview-pane`, at most a third of the content width) and preview-only (Alt+P `toggle-preview-mode`) — are actions over an `AdwMultiLayoutView`; `new_tab` exits preview-only. Detection uses `LushtextEditorPage::document_language_id`, which falls back to the path's language while the document scale holds syntax off, so a gated Markdown file is still previewed. The preview refreshes on tab switch, on buffer changes (300 ms debounce) and through `connect_content_republished` (load publish and failure, buffer-replacement terminals, `republish_document_identity`); a selected Markdown editor that is loading shows `Preparing Markdown preview…`, and `refresh_selected_tab_model_projections` calls `reload_if_evicted` before `refresh_preview`. Showing the side-by-side sidebar on a never-allocated `AdwOverlaySplitView` is deferred to the first frame after allocation (Libadwaita seeds its spring with `0 / 0`). `samples/markdown-test.md` is the showcase of supported preview features; update it when preview behavior changes.
- **Markdown retirement and image admission**: render replacement keeps at most two detached GTK generations plus one deferred request (one more on the terminal escape path); source ownership reserves one plain-data drop slot before planning and carries it through plan and projection, so stale payloads are destroyed on a worker. Buffers, tags, links, embeds and widgets stay on the GTK thread. One `MarkdownPreviewRenderContext` shares the document path and workspace graph; image admission happens before path expansion, candidates are checked one at a time, and every failure keeps the accessible fallback. The `preview-animation` blocker covers planning, projection, images, retirement, layout switches and code-block width repair.

## Testing

- Unit tests: `#[cfg(test)]` modules across models, services, and GTK-free UI helpers; integration tests: `crates/lushtext/tests/integration.rs` (`#[path]` split binary); property tests: `make test-prop`.
- Widget tests: `crates/lushtext/tests/widget.rs` is a custom single-threaded harness that keeps GTK on one thread and self-supervises into a private headless session (the session helper's `widget` profile: a private, monitored system bus, no AT-SPI bus, no portals) before GTK initializes; the launcher sets the recommended environment, including `GTK_A11Y=test` (accessible state stays queryable, no `org.a11y.Bus`) and `ADW_DISABLE_PORTAL=1`, and the per-test child only checks it. **Widget tests never run against the developer's live desktop session.** CI splits the suite into the shards of `scripts/widget-shards.py` (a new widget module file must be assigned to one); locally `make test` runs those shards in parallel. Presented widget tests do not reliably advance `AdwTimedAnimation` frame clocks, so animation-dependent assertions use end-state checks or a narrow `LUSHTEXT_WIDGET_CHILD` immediate-completion path.
- `TestContext`: an isolated tempdir with simulated XDG directories; unit and integration tests pass its explicit directories instead of resolving the global data dir.

The blocking Rust lint gate is curated and all-featured:
`cargo clippy --workspace --all-targets --all-features -- -D warnings`. Local
`make check`, `.githooks/pre-commit`, and CI must stay aligned with that
command (the hook skips only the Clippy step for a docs-only commit, decided

## Async I/O Pattern

Background I/O uses `gtk_lush_tasks::spawn_blocking_then(state, work, then)`:
1. `state` — non-Send GTK object, wrapped in `ThreadGuard` automatically
2. `work` — `FnOnce() -> T + Send`, runs on a background thread
3. `then` — `FnOnce(state, T)`, runs on the main thread from one completion source at `gtk_lush_tasks::completion_priority()` (`GDK_PRIORITY_REDRAW + 4`)

`ThreadGuard` implements `Send` and asserts same-thread access on `.into_inner()`.

**Concurrency guard:** `spawn_blocking_then` limits outstanding work to `DEFAULT_MAX_CONCURRENT_SPAWNS = 8`. The slot stays held until the completion has consumed the result, so large completed results cannot pile up outside the cap; work over the limit waits in a GTK-main-thread FIFO.

**Completion priority:** completions run one step above GtkTextView's incremental validation idle (`GDK_PRIORITY_REDRAW + 5`, ledger A80) and below frames, resizes and input; the source runs completions back to back and yields to lower priorities after `COMPLETIONS_BEFORE_YIELD` (8) of them or `COMPLETION_RUN_BUDGET` (16 ms), whichever comes first. A completion callback runs ahead of text layout: **keep it within `B_SETTLE_US` and move larger work into bounded continuations.** Hand-offs between bounded stages (the load and save admission drains and their permit releases) run at the same priority; paced work that must follow validation (the post-open install slices, `PACED_SLICE_PRIORITY`, A70) stays below it.

**Fire-and-forget pattern:** for tiny non-critical cleanup with no main-thread callback (temp file cleanup after a failed inline create), raw `std::thread::spawn` is acceptable. Persistent app state writes go through `spawn_blocking_then` so they respect the concurrency guard and serialize correctly.

**Atomic JSON writes:** `json_store::save` streams pretty JSON into the shared durable-write helper: safe temp creation, metadata application, final temp-file sync, `rename`, and parent-directory sync. The file is either fully old or fully new, and the renamed directory entry is durable before success is reported.

**Key constraint:** GTK objects are NOT `Send`/`Sync`. Never pass them directly across threads; always use `ThreadGuard` or `SendWeakRef`.

**TreeListModel caveat:** never set `autoexpand = true` on `TreeListModel` — it recursively calls the child-model callback for every directory, which with background I/O spawns unbounded threads, and with synchronous I/O freezes the UI.

GObject subclassing (`mod.rs` + `imp.rs`, `ensure_type()`, the `AdwApplicationWindow` trait chain), GTK initialization order (CSS in `startup()`), and gtk-rs version alignment are in `.agents/rules/rust.md`. Pre-existing blockers are fixed in the same work stream, with no exceptions (`.agents/rules/preexisting-blockers.md`).
