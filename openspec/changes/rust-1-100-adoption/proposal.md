## Why

Rust 1.100.0 shipped on 2026-11-12. The investigation in `.claude/handoffs/rust-1-100-adoption/proposal.md` (reviewed the same day) found that LushText cannot move its **pin** yet: the shipped Flatpak builds with `org.freedesktop.Sdk.Extension.rust-stable//26.08`, which is still 1.98.0, and the rule in `.agents/rules/build.md` item 5 says the binary we test must be built by the compiler we ship. The pin and the MSRV therefore stay at **1.98.0**.

The investigation also found work that is worth doing now, without moving the pin:

- **A real data-integrity defect (A8), independent of the toolchain.** `rename_durable_no_replace_or_checked` reads any `Unsupported` error as "the kernel lacks `RENAME_NOREPLACE`". The protocol returns its *last* error, and after a successful rename that can be the parent-directory `fsync`. If that sync fails with `EOPNOTSUPP`/`ENOSYS` (both map to `ErrorKind::Unsupported` on 1.98.0), the fallback finds the destination present, because the file was just moved there, and reports `AlreadyExists`. The sidebar then shows "A file named … already exists" for a rename that happened. It skips `rename_callback`, so open tabs keep the old path. For a New File/Folder first name it also deletes the row and schedules cleanup of the already vacated old path. Draft set-aside takes the false `AlreadyExists` for a name collision and moves on with the source already gone. The sidebar's other I/O arm has a wider gap: **any** post-rename durability error (for example `EIO`) leaves the row and the tabs on the old path while the file has moved.
- **Clippy 1.100 would turn `make check` red (A1).** It reports 32 `clippy::map_unwrap_or` (denied in the workspace) and 1 `clippy::needless_bool` in `lushtext-core`, and an estimated 23 more sites in the other members. The fix, `Option::map_or_default`, is stable since 1.98.0 and compiles on Kani 0.68.0's nightly, so it can land today.
- **Cheap guards against the next bump.** A version-policy note (A7: never adopt 1.99.0, which miscompiles FFI `bool` returns on x86_64; 1.99.1 is the floor of any 1.99 pin; the shipped 1.98.0 lacks the 1.98.1 vtable fix). A weekly advisory CI job on the latest stable (A2), so churn like A1 shows up the week it ships. Tooling for Cargo's build-dir layout v2: nextest ≥ 0.9.143 and the `lint-advisory.py` generated-path regex (A4). An empty `[lints]` table in `workspace-hack` (A3).
- **A dependency cooldown (A6).** Cargo 1.100 stabilised `registry.global-min-publish-age`. A 7-day cooldown, run with cargo 1.100 and the MSRV-aware fallback, hardens the supply chain without moving the pin. The workspace uses `resolver = "2"`, which is not MSRV-aware, so the fallback must be requested explicitly, and a `cargo +1.98.0` check proves the result.

The same change also takes **sourceview5 0.11.3** (released 2026-11-14). It contains the upstream fix LushText reported (sourceview5-rs#19, merged as !42): `SearchContext::replace_all` now returns `Result<u32, glib::Error>` and no longer panics when nothing matches. That retires the one `unsafe` FFI block in `ui/search_bar/execution.rs`. It belongs here because it regenerates the same `Cargo.lock`, `workspace-hack` and `build-aux/cargo-sources.json` as A6, and generated files cannot be text-merged across parallel branches.

## What Changes

- **A8, durable rename classification.** `RenameProtocol` (the I/O-free core in `services/filesystem/write_protocol.rs`) classifies its terminal the way `WriteProtocol` does: success, before-rename (the rename step failed, nothing moved), or after-rename (a directory sync failed, the rename took effect). The shell maps that class to `DurableWriteError`. The no-replace fallback runs only on a **before-rename** `Unsupported`. `rename_durable_no_replace_or_checked` returns the classified error. The sidebar treats an after-rename result as a completed rename: paths, cache, watch and the rename/create callbacks all run, and the user gets a warning that LushText could not confirm the change reached the disk. Draft set-aside treats it as placed. A new Kani harness proves the rename classification sound, and shard `core-journal-and-write` reruns once.
- **A1, Clippy 1.100 sweep.** Run Clippy 1.100 over the whole workspace and fix every new site (`map(f).unwrap_or_default()` → `map_or_default(f)`, `needless_bool`, and anything else 1.100 reports workspace-wide) with APIs available at the 1.98 MSRV. Both the 1.100 run (`-D warnings`) and `make check` on 1.98.0 must be clean. The optional `manual_bit_width` edit to a Kani-proved `const fn` is **declined**, because it is pedantic, not enabled, and would cost a shard rerun.
- **A7, version policy** in `.agents/rules/build.md`: never 1.99.0, 1.99.1 is the floor of any 1.99 pin, and the shipped 1.98.0 lacks the 1.98.1 vtable fix.
- **A2, weekly advisory "next stable" workflow**: Clippy and check with the latest stable toolchain, forced over `rust-toolchain.toml`. It is not a required check and never gates a PR.
- **A4**: the CI pin `CARGO_NEXTEST_VERSION` moves 0.9.137 → **0.9.151** (≥ 0.9.143; the newest release older than the 7-day cooldown). `scripts/lint-advisory.py` accepts layout-v2 generated paths `/build/<pkg>/<hash>/out/` as well as v1 `<pkg>-<hash>`.
- **A3**: an empty `[lints]` table in `workspace-hack/Cargo.toml`, outside the hakari section. The `unused_dependencies` half needs `[lints.cargo]`, which cargo 1.98 rejects as an unused key, so it waits for the pin (proposal B2).
- **A6, `make update-deps-cooldown`**: `cargo +1.100.0 update` with `CARGO_REGISTRY_GLOBAL_MIN_PUBLISH_AGE="7 days"` and `CARGO_RESOLVER_INCOMPATIBLE_RUST_VERSIONS=fallback`, then `cargo hakari generate`, `make cargo-sources`, a `cargo +1.98.0 check` and `cargo deny check bans`. The target is applied once in this change. Measured: it refreshes **129 packages**, and two duplicate majors then fail `cargo deny check bans` (`multiple-versions = "deny"`). `syn` 2/3 comes from clap_derive 4.6.7, and `system-deps` 7/9 from gtk-rs-core's `*-sys` 0.22.9 against libadwaita-sys/sourceview5-sys. Both duplicates are upstream-structural, so they get version-scoped, reasoned `skip` entries in `deny.toml`, each with a removal condition. Side lockfiles (`fuzz/Cargo.lock`, `fixtures/gtk-lush-adoption/stock-settle/Cargo.lock`) are refreshed the same way, or their deferral is recorded.
- **sourceview5 0.11.3 (manifest-range change).** The workspace floor moves `sourceview5 = "0.11"` → `"0.11.3"`, because the safe binding's `u32` return exists only from 0.11.3. The cooldown refuses that release until 2026-11-21 08:57 UTC, and `--precise` is refused under the cooldown too (measured). The **recorded exception** is applied after the cooldown refresh, without the cooldown: `cargo +1.100.0 update -p sourceview5 -p sourceview5-sys --precise 0.11.3`. Until it expires, `make update-deps-cooldown` fails loudly on the floor. Cargo has no per-package override, and `CARGO_RESOLVER_INCOMPATIBLE_PUBLISH_AGE=allow` would disable the whole cooldown (measured). `replace_all_occurrences` becomes `context.replace_all(..)`, and the `unsafe` block goes.
- **Docs**: `build.md` (version policy, cooldown procedure and its exceptions, nextest floor, the advisory lane as an explicit exception to "every CI toolchain step pins 1.98.0"), `README.md` if build commands change, `crates/lushtext-core/src/ui/editor_page/AGENTS.md` (the FFI note), `docs/upstream-reports.md` (sourceview5-rs#19 released and adopted), the sidebar `WFR-*` matrix row, and the programme record.

No persisted format, GSettings key, action, D-Bus member, automation snapshot field, readiness predicate or accessible name changes. The one user-visible change is the sidebar's new durability warning, which replaces a false "already exists" warning or a silent stale state.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `durable-file-write-contract`: the no-replace rename falls back only on a before-rename `Unsupported`, callers treat an after-rename failure as a completed rename, and the rename classification is proved in the verified core.
- `rust-toolchain-adoption`: the toolchain version policy, the weekly advisory next-stable lane, and build tooling that tolerates Cargo's layout v2. The guidance requirement's stale "1.98.1" is corrected.
- `rust-linting-policy`: the workspace stays clean under the next stable Clippy, fixed with MSRV-compatible APIs.
- `dependency-surface-maintenance`: refreshes observe a publish-age cooldown and the MSRV, with recorded exceptions and reasoned duplicate skips.
- `search-replace-safety`: in-tab Replace All uses the safe GtkSourceView binding and reports its count.
