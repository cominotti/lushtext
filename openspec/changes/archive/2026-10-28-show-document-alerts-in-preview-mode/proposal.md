## Why

In Markdown preview-only mode (`Alt+P`, `win.toggle-preview-mode`), a file that changes on disk never shows its yellow "File Has Changed on Disk" alert. The user has to leave preview mode to see it. The alert is a `LushtextInfoBar`, a child of each `LushtextEditorPage` (`resources/ui/editor-page.blp`). Every page sits in `tab_view` inside `editor_box`, which is the `[editor]` slot of `preview_layout_view` (`resources/ui/window.blp`). The `preview` `Adw.Layout` places only the `preview` slot, and `apply_preview_shell_state` also hides `editor_box`. So the whole editor is off screen, banner included. LushText does not auto-reload, so in preview-only mode the user reads stale content and gets no signal.

Every other editor inline alert has the same blind spot: the restored-draft and stale-draft alerts, "Could Not Open File", "Loading Cancelled", "Mixed Line Endings Detected", "Restored from Local History" (Undo Restore), "Draft Not Restored", and "Automatic Recovery Paused". Every one of them describes the document, not the editor widget. The principle agreed with the maintainer: **a document-state alert is visible on every surface that shows the document.**

## What Changes

- **A second presentation of the selected tab's alert, directly above the Markdown preview.** `resources/ui/window.blp` wraps `preview_layout_view` in a vertical `Box` whose first child is a second `LushtextInfoBar`, `preview_document_alert`. The Markdown preview widget itself is not edited. The notes browser and note editors build their own previews, and they must not each carry a dead alert. The window's notification workflow (`ui/window/notifications/`) projects the **selected** tab's current inline notification onto it, read from the same `NotificationBus::editor_info_bar_view` the editor's own bar renders from. It has the same title, body, style, and buttons. The per-editor info bar is not moved, reparented, or duplicated in state.
- **Shown only while preview-only is active.** In editor-only and side-by-side layouts the editor's own bar is on screen, so the preview copy stays hidden and the user never sees two banners. The side-by-side split never collapses into an overlay. Its pane is at most one third of the content width, so the editor's banner is never covered. The copy shows whatever the preview is displaying: rendered Markdown, the "Preparing Markdown preview…" placeholder, or "Not a Markdown file".
- **Same handlers, by construction.** A button on the preview copy forwards to the selected editor's own info bar, which runs the closures `wire_info_bar` installed: Retry, Discard Changes and Reload / Discard / Normalize… / Undo Restore / Show in Local History, Save, and Dismiss. The forward is guarded: a click acts only if the selected tab and its alert are still the ones that were projected. That matters when the selection changed during a deferred tab-projection batch. Either surface's action updates both, because both re-render from the bus.
- **One projection entry point.** The existing full pass runs from every bus publish, dismiss, resolve, and expiry sweep, from every preview-mode change (`apply_preview_shell_state`), and from every selected-tab change (`refresh_selected_tab_model_projections`). There is no second, narrow path.
- **An alert is announced exactly once, when it first becomes perceivable.** That moment is one of: the alert appears on the visible editor; preview-only is entered with an unannounced alert; a background tab whose alert was raised while it was hidden is selected. An alert raised on a hidden background tab is not announced when it is raised. Re-entering preview-only, re-rendering, switching tabs back, and other tabs' activity announce nothing. The decision moves from the widget's render into the projection pass, which keeps a per-window ledger of announced alert keys.
- **Pre-existing defects fixed in the same stream** (`.agents/rules/preexisting-blockers.md`):
  - *Load success hides the alert behind the bus's back.* `load::execution` calls `editor.clear_inline_notification()`, which hides the widget but leaves the bus record. The next full pass, such as any status message, brings it back. Three production paths reach load success without a dismiss: the eviction reload, the Replace All target reload, and reopen with encoding. Load success now resolves the record through the bus, but only for alerts the loaded bytes supersede. Recovery alerts that point at a preserved draft ("Draft Not Restored", "Draft Restore Failed") outlive a reload.
  - *Inline alerts re-announce on unrelated passes.* `Error` alerts bypass the throttle, so every pass re-announces them. Warnings are re-announced by any pass after the 2 s cooldown. Background tabs announce too, from unmapped widgets.
  - *The status lane has the same defect.* `StatusBar::render_message` re-announces a visible error status on every pass until it expires. The status announcement moves to the Acknowledge stage, beside the pulse.
  - *A cancelled "Normalize…" makes the same button silently reload the file.* The discard handler consumes `PendingWarningAction`. After the line-ending dialog is cancelled, the next click falls through to dismiss-and-reload and drops unsaved edits. The handler now reads the action without consuming it.
- **Evidence surface:** the ledger, the projection ticket, and the per-surface announcement counts are workflow state outside the bus, so `WFR-STATUS-NOTIFICATIONS` gains `ui/window/notifications/evidence.rs` (`NotificationEvidence`). That retires the row's recorded "no evidence surface" conclusion.
- **Automation:** a new bounded snapshot field `surfaces.preview_document_alert_visible` (`bool`), projected from the evidence surface. Documented in `docs/automation.md` and `docs/automation-reference.md`, with a stable AT-SPI anchor row for the preview copy's alert.
- **Tests:** widget tests in `crates/lushtext/tests/widget/window_preview.rs` for the external-change and Reload flow in preview-only, exactly one visible alert in side-by-side, tab-switch re-projection and clearing, forwarded actions, the deferred-batch stale forward, focus, multi-window independence, and narrow-width wrapping. Failing-first regressions for each pre-existing defect. Unit tests for the new pure policy. An accessibility widget assertion, an accessibility-smoke case, and a visual-smoke scenario, both named `preview-mode-document-alert`.
- **Docs:** `docs/workflow-readability-matrix.md` (`WFR-STATUS-NOTIFICATIONS` re-derived, the new `evidence.rs` declared), the notifications facade narrative, `docs/accessibility.md`, `docs/accessibility-matrix.md`, `docs/accessibility-orca-checklist.md`, `docs/end-user-coverage.md`, README (Notes, History, and Preview), AGENTS.md (module layout and the inline-alerts, status-bar, and Markdown-preview design decisions), and `.agents/rules/ui.md` (the Inline Alerts section).

No persisted format, GSettings key, action, D-Bus method, or readiness predicate changes. One new module file: `ui/window/notifications/evidence.rs`.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `editor-inline-alerts`: adds requirements that a document-state inline alert is also presented on the preview-only surface for the selected tab, with the same actions, consistent state across both surfaces, re-projection on tab switch, exactly one visible banner in every layout, one announcement when the alert first becomes perceivable, no repeated status-lane announcements, constrained-width wrapping on the preview surface, per-window independence, a non-consuming warning action, and that a successful load resolves superseded alerts through the notification bus while recovery alerts survive.
- `external-file-monitor-coverage`: adds a requirement that an external modification is covered end to end in preview-only mode: the warning shows on the preview surface, and Reload refreshes the rendered preview.
- `dbus-automation-spine`: adds a requirement for the `surfaces.preview_document_alert_visible` snapshot field and its documentation.

## Impact

- **Code:** `resources/ui/window.blp` and its generated `.ui`, `resources/ui/template-contract.json`; `ui/window/imp.rs` (template child, `LushtextInfoBar::ensure_type()`, ticket and ledger state); `ui/info_bar/{mod.rs,imp.rs}` (silent render, `announce`, `activate`); `ui/status_bar/mod.rs` (silent render, announcement called from stage 3); `services/notifications.rs` (GTK-free `InlineAlertAction`); `ui/window/notifications/{mod.rs,policy.rs,execution.rs,evidence.rs}` (projection, ledger, forward guard, focus handoff, evidence); `ui/window/preview.rs` and `ui/window/documents.rs` (re-projection call sites, the non-consuming warning action, the superseded-by-load callback); `ui/window/tab_strip/close_execution.rs` (ledger entry dropped on detach); `ui/editor_page/mod.rs`, `ui/editor_page/load/{execution.rs,retirement.rs}`, `ui/editor_page/monitor.rs`, `ui/window/drafts/restore_execution.rs`, `ui/window/local_history/restore_execution.rs` (emit variants that state whether a load supersedes the alert); `ui/automation.rs` and `model/automation.rs` (snapshot field). `ui/markdown_preview/**` is not changed.
- **Tests:** `crates/lushtext/tests/widget/window_preview.rs`, `window.rs` (resurrection and recovery-alert-survival regressions, the Normalize regression), `editor_page.rs` (the windowless path keeps its throttled announcement), `status_bar.rs` (status announcement on acknowledgement only), `accessibility.rs`; `scripts/run-accessibility-smoke.sh` and `scripts/run-visual-smoke.sh` cases; unit tests in `notifications/policy.rs`.
- **GTK axioms:** none added up front. One possible axiom, `AdwDialog` focus return to a hidden widget, is measured by task 6.4 (see design.md, "GTK axioms").
- **Risk:** low to moderate. The change adds one hidden-by-default widget per window and moves two announcement decisions into the projection pass. It narrows when alerts and status errors are re-announced, which is intended and covered by tests. The superseded-by-load classification changes what a reload clears. The table in design.md D7 records it, and regression tests cover both directions.
