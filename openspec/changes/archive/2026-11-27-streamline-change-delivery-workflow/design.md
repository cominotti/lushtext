# Design: Streamline Change Delivery Workflow

Timing: none (no timed path touched)
Ledger axioms relied on: none (no toolkit behaviour changed)
Budget exceptions: none

## Context & Problem

Measured across five sequential OpenSpec changes (~20.75 h / 1,245 min), ~60% of wall time went to repeated UI smokes (~449 min across 26–28 runs under Mutter), separate docs-only archive PRs + CI waits (~202 min), and repeated commit-hook Clippy runs (~42 min). Earlier decisions recorded in `docs/memorials/2026-11-18-change-flow-time.md` — Decision 7 (exclude `crates/lushtext/tests/widget/` from smoke fingerprints), Intervention 2 (parallel smoke execution), and Intervention 4 (tree-hashed `make check` stamp for `pre-commit`) — remain unimplemented, and `scripts/check-accessibility-policy.py` still records hole S7(b) (committed clean trees bypass smoke freshness).

## Decisions

### D1. Decouple static `pre-commit` from branch-level `pre-push` smoke enforcement (and close S7(b))
- **Decision:** Keep `.githooks/pre-commit` focused on fast static gates (`make pre-commit` or `make pre-commit-docs`), skipping redundant Clippy+policy via a clean-worktree `git write-tree` stamp (`scripts/precommit-scope.py stamp-write` / `stamp-valid`, 30-minute TTL, bypassed by `MERGE_HEAD` or `LUSHTEXT_SKIP_PRECOMMIT_STAMP=1`) when `make check` already passed on that exact tree. **Both `stamp-write` and `stamp-valid` enforce the exact same clean-worktree (`git diff --quiet` and zero untracked files) and no-`MERGE_HEAD` preconditions**: if the worktree is dirty or merging, `stamp-write` deletes any stale stamp and writes nothing. Inside `make check-policy`, `make check-accessibility-policy` runs `--static-only` and `make check-visual-proof-policy` runs `./scripts/check-visual-proof-policy.py --self-test` (Python + Rust parity self-tests) only. Live smoke freshness (`check-accessibility-policy.py --strict-current-tree --base-ref` and `cargo run -q -p cargo-gtk-proof -- policy --base-ref`) moves to `make check-smoke-proof`, enforced by `.githooks/pre-push` and `make verify-local` against `origin/main...HEAD`.
- **Rationale:** Allows checkpoint commits and `/swarm` worker integration without paying 26–28 redundant Mutter runs, eliminates ~42 min of duplicate `git commit -S` Clippy runs, prevents dirty-worktree stamp poisoning (`stage A -> dirty B -> make check -> checkout -- B -> commit A`), and closes recorded hole S7(b) so committed UI diffs cannot reach remote branches or `main` without fresh smoke proofs.
- **Rejected alternatives:**
  1. *Keep live smoke freshness inside `pre-commit` and rely solely on agent discipline:* Rejected because checkpoint commits or review fixes touching `ui/` still re-trigger all 3 smokes and hole S7(b) remains open on committed/merged branches.
  2. *Keep an unbounded stamp TTL or omit clean-tree check in `stamp-write`:* Rejected; either allows stale or unchecked trees to skip `pre-commit`.

### D2. Exclude `crates/lushtext/tests/widget/` from smoke source fingerprints (2026-11-18 Decision 7)
- **Decision:** Remove `crates/lushtext/tests/widget/` from `RELEVANT_PREFIXES` (`scripts/accessibility_source_fingerprint.py`) and `VISUAL_SENSITIVE_PREFIXES` (`scripts/check-visual-proof-policy.py` and `crates/cargo-gtk-proof/src/policy.rs`), keeping it in `is_policy_path` (`scripts/check-accessibility-policy.py`) so static accessibility checks still run on widget tests. Add parity assertions in both Python and Rust self-tests.
- **Rationale:** Widget test files never compile into the shipped `lushtext` binary (`cargo check -p lushtext --bins --locked`) and are already verified by `make test-widget-headless`. Residual risk (declared in `testing.md`): an edit solely under `crates/lushtext/tests/widget/` cannot alter production rendering or AT-SPI behavior, only test coverage.
- **Rejected alternative:** Keep `tests/widget/` in smoke fingerprints — wastes a full Mutter trio whenever a widget test is added or adjusted.

### D3. Parallel smoke runner (`make smoke-ui`)
- **Decision:** Add `make smoke-ui` (`SMOKE_PARALLEL=1` default, `SMOKE_PARALLEL=0` serial fallback). It pre-builds `build-debug`, `smoke-read-faults-build`, `composition-hold-build`, and `cargo-gtk-proof` once sequentially (avoiding Cargo target-dir lock contention), then runs `accessibility-smoke`, `visual-smoke`, and `visual-geometry-smoke` concurrently under `scripts/heavy.sh --envelope 16G`, failing closed if any lane exits non-zero. When `GATE_TREES_CHANGE=<change>` is set, each lane runs through `scripts/gate-trees.sh record` under its exact canonical `GATE_NAMES` string (`make accessibility-smoke`, `make visual-smoke`, `make visual-geometry-smoke`) with `flock` serialization in `gate-trees.sh` so concurrent appends never interleave.
- **Rationale:** Cuts the single UI smoke pass from ~15–20 min serial to ~6–8 min wall time while keeping each runner inside its own `with-temp-scope.sh` root and private Mutter compositor and recording canonical `gate-trees.sh` entries cleanly.
- **Rejected alternative:** Running `make smoke-ui` without pre-building shared binaries first — rejected because concurrent `cargo build` invocations contend on `target/` locks.

### D4. Commit-invariant visual proof digests (`changed_files_digest`)
- **Decision:** Update `changed_files(base_ref, root)` in both `crates/cargo-gtk-proof/src/policy.rs` and `scripts/check-visual-proof-policy.py` so when `base_ref` is given (or `GITHUB_BASE_REF` is set), it returns the sorted union of `base_ref...HEAD` and `git status --porcelain`. Pass `--base-ref <ref>` from `cargo-gtk-proof run` (when supplied by `Makefile` `visual-geometry-smoke` if `$(SMOKE_PROOF_BASE_REF)` resolves) into `current_visual_proof_policy_metadata`.
- **Rationale:** Previously, `visual-geometry-smoke` digested `status_changed_files()` (dirty files) while `--base-ref` policy check digested `origin/main...HEAD` (committed files), causing digests to mismatch right after committing. Unioning both makes the digest invariant across `git add` and `git commit` as long as file bytes do not change, matching `accessibility_source_fingerprint.py`.
- **Rejected alternative:** Always forcing users to run `make smoke-ui` *after* committing — rejected because uncommitted pre-push fixes or final staging checks would still mismatch if computed inconsistently.

### D5. Single local CI-parity target (`make verify-local` & `make verify-local-fast`)
- **Decision:** Add `make verify-local-fast` (`check`, `cargo check -p lushtext --bins --locked`, `rustdoc` lints with `-D rustdoc::broken_intra_doc_links -D rustdoc::private_intra_doc_links -D rustdoc::bare_urls`, `cargo bench --no-run`) and `make verify-local` (adding `cargo deny`, `make test`, `make test-prop`, `make fuzz-corpus-replay`, conditional GTK Lush checks when `crates/gtk-lush*` changed, optional `VERIFY_RUN_SMOKES=1`, and `make check-smoke-proof`).
- **Rationale:** Eliminates forgotten local checks (`rustdoc`, `bench --no-run`, `fuzz-corpus-replay`) that previously caused ~15 min CI fix-push cycles.
- **Rejected alternative:** Leaving `rustdoc` and `bench --no-run` as manual checklist items — proven error-prone across Changes 1–4.

### D6. Review-Before-Smoke, Archive-Before-Final-Gate, and `programme-change.js` Alignment
- **Decision:** Standardize the 6-phase workflow for `/goal` and standalone agent workflows in `.agents/skills/change-delivery/SKILL.md` and `.agents/rules/{parallel-agent-work,verification-runs,testing,build}.md`:
  1. Non-UI foundation commits freely (`pre-commit` static + tree stamp);
  2. UI edits batched without intermediate smokes (`/swarm` workers return patches or commit without pre-commit smoke churn);
  3. `/swarm` 3-lens code review + all review fixes **before** running smokes;
  4. Commit final code, then commit `openspec sync + archive` (docs-only) on the same PR branch (**Archive-Before-Final-Gate**, whenever no Kani CI shard figures are pending);
  5. Run ONE single final gate pass (`make smoke-ui GATE_TREES_CHANGE=<C>` when UI-relevant + `make verify-local`, plus `scripts/gate-trees.sh record` recording canonical `GATE_NAMES`: `'make check'`, `'make test'`, plus `'make accessibility-smoke'`, `'make visual-smoke'`, `'make visual-geometry-smoke'` when UI-relevant — and optionally `'make verify-local'` explicitly since `gate-trees.sh lookup` matches exact `--gate` strings) on that **exact final post-archive `HEAD^{tree}`**, then merge PR under `$H/MERGE-LOCK` using `gate-trees.sh` local evidence (extended to any authorized `/goal` or agent workflow);
  6. Asynchronous CI/Sonar audit after merge (except `.github/workflows/**` changes, which still watch live CI before `MERGE-LOCK`).
  - **Minimal `programme-change.js` alignment**: Keep `.claude/workflows/programme-change.js`'s stage graph, post-merge archive path (`OWED_FIELDS` / `MERGE_COMMITS`), and all cited rule section headings untouched, while updating `smokeCheck()` + `apply-verify` + `programme-change.test.mjs` so `programme-change.js` no longer treats ordinary non-merge UI commits as already smoke-checked by `pre-commit` (`"hook"`), and instead requires `gate-trees.sh` smoke records whenever `origin/main...HEAD` touches `is_relevant` files.
- **Rationale:** Running In-PR archive *before* the single final gate pass preserves the exact-`HEAD^{tree}` invariant (the merged tree itself carries every `gate-trees.log` pass under canonical `GATE_NAMES`) while eliminating separate archive PRs (~96 min CI wait + ~32 min subagent overhead). Updating `smokeCheck()` prevents `programme-change.js` from silently skipping smoke verification after D1 removes live smokes from `pre-commit`.
- **Rejected alternative:** Leaving `programme-change.js` `smokeCheck()` trusting `"hook"` after D1 moves smokes to `pre-push` — rejected because `programme-change.js` would accept non-merge UI commits without `gate-trees.sh` smoke records.

### D7. Zero-cost structural refactor `Timing: none` exemption
- **Decision:** Allow pure structural/type-safety refactors (e.g., `#[repr(transparent)]` value wrappers, error enum typing, crate/module splits without control-flow or runtime logic changes) on timed paths to declare `Timing: none (zero-cost structural refactor: <reason>)` in `design.md` and `tasks.md`, confirmed by **both** independent spec review (design intent) and final/code review (verifying the implemented diff introduces no new allocation, clone, lock, or dispatch change).
- **Rationale:** Avoids ~90 min of `measure.sh` overhead on zero-cost refactors while keeping full `measure.sh` verdicts mandatory whenever runtime execution paths, allocations, concurrency, or budgets change.
- **Rejected alternative:** Relying on spec review alone — rejected because implementation details (e.g. an added `.clone()` or allocation) are only visible once code is written.

### D8. Zero-dependency Python hygiene check (`scripts/check-python-hygiene.py`)
- **Decision:** Add `scripts/check-python-hygiene.py` (wired into `make check-policy` and CI `lint`) scanning repo-owned Python scripts (`scripts/*.py`, `.agents/skills/**/scripts/*.py`) using stdlib `ast` + regex alternation analysis to catch syntax errors, bare `except:`, duplicate dict keys, and redundant regex alternatives (`python:S5855` style, suppressible per line with `# python-hygiene-ok: <reason>`).
- **Rationale:** Prevents late CI Sonar pushes (`python:S5855` on PRs #136/#140) with zero external dependencies.
- **Rejected alternative:** Requiring `ruff` in Fedora CI containers and developer hosts — adds an external tool dependency not guaranteed in all environments.

### D9. CI docs-only fast path preserving Ruleset `23911547` required checks
- **Decision:** Add `docs-only-range <base> <head>` to `scripts/precommit-scope.py` and a `scope` job to `.github/workflows/{ci,kani,flatpak,snap,sonarqube}.yml`. Non-required jobs skip cleanly when `docs_only == 'true'`. The 5 jobs carrying GitHub Ruleset `23911547` required status checks (`GTK Axioms`, `GTK Axioms (GNOME 50 floor)`, and the 3 PR `Kani Proof Harnesses (...)` matrix jobs) **remain executed** (no job-level `if:` skip!) and short-circuit their heavy `dnf`/Rust/Kani steps with a fast `step`-level `if: needs.scope.outputs.docs_only != 'true'`, emitting green `Success`.
- **Rationale:** GitHub rulesets block merging when a required check is `Skipped`; step-level short-circuiting achieves ~30 s green PR completion on docs-only PRs while preserving 100% ruleset compliance on code PRs.
- **Rejected alternative:** Job-level `if:` on `gtk-axioms` / `kani` — rejected because GitHub treats `Skipped` required checks as blocking unless bypassed with `--admin`.
