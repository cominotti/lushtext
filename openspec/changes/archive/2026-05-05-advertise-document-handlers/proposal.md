## Why

LushText can open text and Markdown documents, but its desktop metadata does not fully advertise the document types GNOME Settings uses for the per-app "Files & Links" section. Users should be able to choose LushText as the default app for plain text, Markdown, and empty documents from GNOME's standard app-association UI.

## What Changes

- Advertise LushText as a handler for empty documents using the freedesktop MIME type `application/x-zerosize`.
- Preserve and verify LushText's existing support for plain text through `text/plain`.
- Preserve and verify LushText's Markdown support through canonical `text/markdown`; `text/x-markdown` remains covered by the platform MIME alias rather than becoming a separate primary contract.
- Ensure installed and development desktop-entry exports refresh their MIME cache so GNOME Settings and `gio mime` see the same handler set.
- Add deterministic validation for desktop metadata and GLib MIME registration after installation/export refresh.

## Capabilities

### New Capabilities
- `desktop-document-handlers`: Covers LushText's advertised desktop document associations and the GNOME/GLib behaviors that make those associations visible in Settings > Apps > LushText > Files & Links and usable as defaults.

### Modified Capabilities

None.

## Impact

- Affected files: `data/dev.cominotti.lushtext.desktop.in`, development desktop-entry staging scripts or Makefile targets that mirror this desktop file, and packaging verification commands.
- Affected systems: GNOME Settings app details, GLib/GIO application association lookup, Flatpak desktop exports, local development desktop exports, and desktop MIME caches generated by `update-desktop-database`.
- No Rust application behavior, document loading, Markdown rendering, or data persistence changes are expected.
