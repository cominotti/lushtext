## Why

LushText's GNOME Settings file-type list currently mixes core document formats with programming-language source types. The app should present a smaller, intentional document-handler contract that matches the file types users should reasonably choose LushText for from GNOME Settings.

## What Changes

- Advertise LushText only for this curated document MIME set: `text/plain`, `application/x-zerosize`, `application/json`, `application/json5`, `application/toml`, `application/yaml`, and `text/markdown`.
- Keep JSONC and Properties documents out of this change because the target desktop stack does not expose stable standard MIME types for those rows without extra shared-MIME definitions.
- **BREAKING**: Remove programming-language source associations from the shipped and development desktop entries, including C source, C header, Python, and Rust MIME types.
- Preserve the existing guarantee that installing, building, or staging LushText registers available handlers without changing the user's default application choices.
- Preserve deterministic validation through generated desktop metadata checks, desktop MIME cache refresh, and `gio mime` visibility checks.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `desktop-document-handlers`: Change the advertised document-handler contract from a minimum set to an exact curated MIME allowlist, and require programming-language source MIME types to be absent.

## Impact

- Affected files: `data/dev.cominotti.lushtext.desktop.in`, local development desktop-entry staging paths, and packaging or verification scripts that inspect desktop MIME handlers.
- Affected systems: GNOME Settings > Apps > LushText > File Types, GLib/GIO application association lookup, Flatpak desktop exports, local development desktop exports, and desktop MIME caches generated by `update-desktop-database`.
- No Rust editor behavior, document loading, syntax highlighting, Markdown rendering, session restore, draft handling, or file I/O behavior changes are expected.
